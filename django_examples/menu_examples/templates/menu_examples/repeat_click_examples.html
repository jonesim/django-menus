Repeat clicks on menu links

Most menu items point at a view that just shows a page, where clicking twice costs nothing. Some point at a view that does something — and a double-click sends that URL twice, so a view which works out what to act on from its own current state acts on both.

The counter below is bumped by exactly that kind of view: it counts every request it is sent, then redirects back here. It also sleeps for a second before answering — the guard drops a click that repeats a navigation already under way, so there has to be a window in which one is. A real server doing real work supplies that; a local runserver answering instantly would close it, and this page would demonstrate nothing.

Also worth trying: click a held button once, wait for the page to come back, then click it again — it counts each time, because only a repeat of a click already navigating is dropped, never a deliberate second one. And double-click A javascript: item: its counter goes up by two, because the page never went anywhere, so nothing is held however fast you click.

Showing that the click registered

Watch a held button during the second the server is busy: it fades. Swallowing the second click stops the duplicate request, but people double-click because the first click appeared to do nothing — so a held link carries a django-menus-clicked class for you to hang that feedback on. No styling ships with it; this page adds its own rule: 

a.django-menus-clicked { opacity: .65; cursor: default; }

Style the appearance only. pointer-events: none looks like the obvious choice and lets the click fall through to whatever sits underneath, which inside a dropdown is another menu item — and the click is already stopped in JS, so the class only has to look the part. It clears when the hold expires, so a navigation that never arrives cannot leave a link looking permanently dead.

Using it

Give the milliseconds to hold a link for at whichever level fits. They cascade item → menu → page → off, so the narrowest one set wins: 

# one item - usually the one that knows it minds being clicked twice
MenuItem('bump_counter', 'Bump the counter', django_menus_repeat_click_ms=2000)

# every item in a menu that has not set its own
HtmlMenu(request, 'button_group', django_menus_repeat_click_ms=2000)

# a page, or a whole site if set on a base view class
class MyView(MenuTemplateView):
    repeat_click_ms = 2000

The first two render a data-django-menus-repeat-ms attribute on the anchor and need nothing else. The view attribute reaches the page through the django_menus_script context variable, so output that once in a base template, alongside the include: 

{% templatetag openvariable %} django_menus_script {% templatetag closevariable %}

All it does is set a JS window of the same name, which the guard reads on every click rather than capturing at load — so it can still be changed at runtime, from a console while diagnosing or by a page's own script. Anything that is not a number above zero reads as off.

What it will not do for you

It stops a duplicate click, not a duplicate request. Reload this page after bumping, or press Back and then Forward, and the counter moves again — the guard never sees those. A view that minds being called twice still has to be idempotent; this is the layer in front of that, not a replacement for it.
