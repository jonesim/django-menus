Repeat clicks on menu links

Most menu items point at a view that just shows a page, where clicking twice costs nothing. Some point at a view that does something — and a double-click sends that URL twice, so a view which works out what to act on from its own current state acts on both.

The counter below is bumped by exactly that kind of view: it counts every request it is sent, then redirects back here. It also sleeps for a second before answering — the guard drops a click that repeats a navigation already under way, so there has to be a window in which one is. A real server doing real work supplies that; a local runserver answering instantly would close it, and this page would demonstrate nothing.

Try it
  1. On the = 0 page, double-click Bump the counter. The counter goes up by two — the view was reached twice.
  2. Reset, switch to the = 2000 page and double-click it again. Up by one.
  3. Still on that page, click it once, wait for the page to come back, then click again. It goes up each time — only a repeat of a click that is already navigating is dropped, never a deliberate second one.
  4. Double-click A javascript: item there. Two alerts: the page never went anywhere, so nothing is held.
Using it

Set the attribute on one view for one page, or on a base view class for a whole site: 

class MyView(MenuTemplateView):
    repeat_click_ms = 2000

It reaches the page through the django_menus_script context variable, so a template has to output it — once, in a base template, next to wherever the django_menus include lives: 

{% templatetag openvariable %} django_menus_script {% templatetag closevariable %}

All the attribute does is set a JS window of the same name, which the guard reads on every click rather than capturing at load — so it can still be changed at runtime, from a console while diagnosing or by a page's own script. Anything that is not a number above zero reads as off.

What it will not do for you

It stops a duplicate click, not a duplicate request. Reload this page after bumping, or press Back and then Forward, and the counter moves again — the guard never sees those. A view that minds being called twice still has to be idempotent; this is the layer in front of that, not a replacement for it.
